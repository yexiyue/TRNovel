# Design: global-settings-page

## D1 为什么是独立页面，而不是把浮层做大

浮层挂在阅读页上，天然受「正文还要看得见」的约束：26 行终端里超过 6 项就会盖住正文大半。设置页是独立路由，可以占满整屏，容纳分组、长路径、构建信息这些浮层放不下的内容。

两类界面因此各司其职：

- 阅读浮层（`o`）= 读到一半想改排版，4 项，不打断阅读。
- 全局设置页 = 装配与排查，分组齐全，可以慢慢看。

两者共用 `describe_setting` / `adjust`，条目序号与文案只有一份，新增条目时不会出现两套编号。

## D2 条目序号即协议

`describe_setting(config, row, page_step)` 的 `row` 是全局序号：0 翻页重叠、1 显示标题、2 段间空行、3 首行缩进、4 每行字数、5 左右留白、6 边框、7 边框标题、8 快捷键提示、9 ↑/↓ 翻页、10 跟随朗读（仅 TTS 构建），末尾是「目录占宽」（`TOC_ROW = 10 + cfg!(feature = "tts")`）。

设置页用 `reading_rows() = TOC_ROW + 1` 决定渲染几行，浮层用 `SETTING_ROWS = [4, 3, 2, 6]` 挑行。新增条目要同时改：`describe_setting`、`adjust`、`reading_rows`（以及若涉及 tts 偏移的 `TOC_ROW` 序号）。

## D3 Space 绑在键位表，而不是事件特判

空间键加进 `reader_defaults` 的 `page_down` 绑定列表，而不是在按键分发里写 `if key == Space`。这样：

- 用户在 `keybindings.toml` 里重绑 `page_down` 时，Space 跟着一起失效/改绑，没有「文档说能改、实际改不掉」的暗规则。
- 帮助与提示行按同一份键位表生成，不会出现「提示里没有、实际能用」。

它排在最后一位，`display_first_key` 仍返回 PageDown，提示行宽度不变。

## D4 ↑/↓ 翻页做成运行时按键翻译

`arrows_page` 开启时，`ReadContent` 的 keymap 回调把「实际按下的是 Up/Down、解析出的 action 是 ScrollUp/ScrollDown」翻译成 PageUp/PageDown；不改键位表本身。理由：

- 改键位表会让绑在 `scroll_up` 上的 `k` 一起变成翻页，那不符合「只是把方向键调成翻页」的字面承诺。
- 翻译发生在分发入口，翻页步长、章首/章末二次确认、跟随朗读挂起等逻辑全部复用既有分支，不需要第二份实现。
- 关掉开关即恢复逐行滚动，无需重启。

## D5 数据分组只读

第一版只显示三个目录的绝对路径，不提供「打开目录」「清理缓存」按钮：TUI 里调外部文件管理器要处理平台差异与失败提示，收益不抵复杂度；用户复制路径即可。后续若加，应作为独立能力提出。
