# 设置交互架构审查与简化

日期：2026-11-15。审查基线 `2c84a01`，覆盖 `c04fd5b`、`d675528`、`5d683b6`。用 `git diff 2c84a01...5d683b6` 审查最近三次设置改造。规范来源为 AGENTS、项目开发工作流和 TUI 知识库；需求来源为 `pr-review-fixes`、`settings-tabs-and-controls`、`unify-settings-surfaces` 与 `reader-theme-presets`。历史交互被后续设计替代的部分按当前设计判断。

## Standards

发现 1 项模块职责规则违反、3 项架构改进机会，复查再发现 1 项预览一致性问题，均已处理：

1. 全局页硬编码阅读字段编号及标题，越过阅读模型职责边界。现在由阅读 `Setting` 返回标签、分组、选项与修改规则。
2. 三个宿主重复按键转换并已出现差异。现在共用纯 `navigation::command`，宿主仍持有自己的游标、输入层和业务动作。
3. 阅读字段使用随 TTS feature 改变的数字身份。现在使用枚举，视觉索引仅承担焦点定位。
4. 设置和退出弹窗重复稳定回调实现。现在共用 `hooks::Callback`，封装同步和 Handler 生命周期，保留跨局部重绘的回调测试。

5. 配色基准切换后，派生继承色的预览与保存结果可能不同。现在统一使用 `CustomTheme::palette()` 更新继承字段，并增加派生色一致性回归。

另将共用 UI 拆为标签、表单、选择器和按钮；听书快照模型与操作接线分离；主题列表与配色编辑器分离。将复杂 props 和回调移出宏，使 rustfmt 能正常整理。按 KISS、DRY、YAGNI、单一职责控制边界，没有引入通用表单框架、新 UI 依赖或配置迁移。

## Spec

首次发现 3 项行为遗漏，另发现 1 项误操作；复查补出 1 项显式颜色覆盖边界问题，均已处理：

1. **保存竞态（P1）**：旧后台任务可能在卸载 flush 之后写入旧快照。两处页面改用共享保存 hook，所有写入串行、获得写入权后再读当前 atom；后台任务不再携带页面 State。失败仍允许后续重试。新增延迟写入与最终 flush 的线程回归。
2. **基准继承（P2）**：只改 base 而保留全部旧色，会把未编辑字段误存为覆盖。草稿现在跟踪显式编辑，切换基准更新继承字段，保存仅写实际覆盖；鼠标和键盘共用方法。增加更换基准、只改正文色、序列化后重新加载的测试。
3. **任意颜色预览（P2）**：色块只存在于固定色板中，手输颜色看不到预览。字段行现在显示实际颜色，与部分 hex 和使用说明一起提供反馈。
4. **全局动作误触发（P2）**：在配色方案行按左右键也会跳转。现在动作只响应 Activate，左右键保持在设置页，增加真实终端回归。

5. **显式覆盖保留（P2）**：显式设置的派生色即使等于基础色也应保留，否则自定义强调色会在重开时覆盖用户选色。保存只判断是否显式覆盖，不再按与 base 相等删除。新增保存、重开、再次保存的回归。
